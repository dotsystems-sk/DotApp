# 09 — DotApp.js and Bridge (complete contract)

**`$dotapp` is not jQuery.** No `$`, no `jQuery`, no `$.ajax`.

## Mandatory script

```html
<script src="/assets/dotapp/dotapp.js"></script>
```

This URL is **generated by the framework Bridge route**, not a static asset. It injects per-session random key material (encrypted referer tab token + a key exchange) that powers CRC, CSRF, secure forms and the bridge. Details:

- Requires a usable `HTTP_REFERER` (length ≥ 3) or the route answers **404**.
- A one-time `PUT` to the same URL completes the key exchange.
- Without this script, `<fo-rm>` is never converted, no CRC/CSRF fields are added, and every secure endpoint rejects the request.

Prefer `<fo-rm>` + `{{ formName(...) }}` for all user forms — see [08-FORMS-AND-SECURITY.md](08-FORMS-AND-SECURITY.md) and [examples/EX-01-secure-form-complete.md](examples/EX-01-secure-form-complete.md). `method` and `action` on the opening tag are literal; **MUST NOT** put `{{ }}` inside `<fo-rm …>`.

## 1. Load order and boot

```html
<script src="/assets/dotapp/dotapp.js"></script>
<!-- optional add-ons -->
<script src="/assets/dotapp/dotapp.template.js"></script>
<script src="/assets/dotapp/dotapp.reactive.js"></script>
<!-- module scripts last -->
<script src="/assets/modules/Shop/js/page.js"></script>
```

```javascript
(function () {
  var runMe = function ($dotapp) { /* app logic */ };
  if (window.$dotapp) {
    runMe(window.$dotapp);
  } else {
    window.addEventListener(
      "dotapp",
      function () {
        runMe(window.$dotapp);
      },
      { once: true }
    );
  }
})();
```

| Event | Use |
|-------|-----|
| `dotapp-register` | register plugins via `$dotapp().fn(...)` (fires first) |
| `dotapp` | application logic |
| `dotapp-template-ready` / `dotapp-reactive-ready` | add-on modules loaded |

Both events are dispatched on **`window`**, once, back to back, while `dotapp.js` executes. A script that runs later never receives them — that is why the `if (window.$dotapp)` branch is mandatory. `document.addEventListener("dotapp", …)` never fires. Copy the block above **character for character**; file shape and rules: [26](26-CONTROL-SLICE.md) §3.

`dotapp.js` takes over `<fo-rm>` / `<form>` **once**, when it executes. Load it after the markup (end of `<body>`; the DACore shell does this). A `<fo-rm>` inserted later through `reply.html` is **not** taken over.

## 2. Selector API and its traps

`$dotapp(selector)` returns an instance for the matched elements. `$dotapp()` (no args) is the singleton used for forms, `load`, bridge, variables and plugins.

Common methods: `each, first, last, nth, get, all, length, parent, children, find, next, prev, siblings, closest, is, index, clone, html, text, val, check, attr, removeAttr, prop, data, addClass, removeClass, toggleClass, hasClass, css, optionText, append, prepend, remove, empty, replaceWith, show, hide, toggle, enable, disable, focus, blur, fadeIn, fadeOut, slideDown, slideUp, width, height, on, one, off, live, trigger, form, submit, serialize, load, parseReply, sendInput, bridge, uploadFile, dragAndDropFile, variable, getVariable, computed, databind, hashRouter, validator, twoFactor, autosave, networkwatch, halt, fn`

| Trap | Reality |
|------|---------|
| Getters chain like jQuery | many getters return the **value**, not `this` |
| `.html()` as getter | returns `this` — read the markup with `$dotapp(sel).html().getLastResult()` |
| `.first()` / `.last()` / `.nth(i)` | return a `$dotapp` object; `.get(i)` returns the raw element; `.first(false)` / `.last(false)` return the raw element |
| `.length` | number of matched elements (`$dotapp(sel).length`) |
| `$dotapp(nodeList)` / `$dotapp(array)` | accepted — elements that are not `HTMLElement` are dropped |
| `dotapp.js` older than 2026-11-14 | `.find()` / `.children()` / `.siblings()` / `.clone()` returned an empty collection, `.last()` threw, `.nth()` returned nothing, `.length` was `undefined` — update the framework |
| `.each(fn)` | calls `fn(index, element)` — index first |
| `.val()` on an empty field | returns `null`, not `""` |
| `.on(event, selector, fn)` | not delegated, returns an unsubscribe function — use `.live()` |
| `.live("focus" / "blur")` | never fires (no bubbling) — use `focusin` / `focusout` |
| `$(document).ready` | use the `dotapp` event |
| `$(this)` | `$dotapp(this)` |
| `.on()` for dynamic DOM | use `.live(event, selector, fn)` |
| Empty selection | getters return `null`/`false`; `.html(x)` **throws** — the id in the view and in the JS must match |

Safe pattern:

```javascript
var email = $dotapp('#login [name="email"]').val();   // read into a variable
$dotapp('#login [name="email"]').addClass('ok');       // then act
```

**Use `$dotapp` for the DOM — not `document.getElementById`, `querySelector`, `getAttribute`, `innerHTML`, `classList`, `el.addEventListener`.** The want → write table is [26](26-CONTROL-SLICE.md) §4. Raw DOM is allowed only where `$dotapp` has no method, and inside a `$dotapp().fn` library (§4 below).

## 3. Network: always `load()` for DotApp endpoints

```javascript
// In page code: always through the module request helper (26 §5) — overlay, parseReply, toast, error path.
shopSend("/api/v1/auth/Shop/items/toggle", { item: $dotapp(el).attr("data-item") }, "#shopItemsWrap", function (reply) {
  $dotapp("#shopItemsInner").html(reply.html);
});
```

What the helper wraps — the raw signature:

```javascript
$dotapp().load(url, "POST", payload,
  function (rawText) {              // HTTP 2xx only. rawText is base64 JSON → parseReply(rawText)
    var reply = $dotapp().parseReply(rawText);
  },
  function (status, bodyText) {     // HTTP 4xx/5xx (status = code) and network faults (status = 0)
    // bodyText may still carry a reply: window.dacoreRequestError.message(status, bodyText, "fallback")
  }
);
```

**MUST NOT** call `load()` with no error callback, and **MUST NOT** `return;` silently when `reply.status != 1` — both are how a button ends up doing nothing. `load()` returns a Promise that also rejects on failure; the helper adds `.catch()`.

`load()` adds CSRF fields, computes the CRC, sets the `dotapp: load` header and posts `{ data, crc }`. Raw `fetch` / `$.ajax` will **fail `crcCheck()`** on the PHP side.

`$dotapp().parseReply(text)` is required because PHP `ajaxReply()` returns **base64-encoded JSON**. For a body that is **not** base64 JSON (`Response::json()`, a PHP warning, an HTML error page) it returns the **raw string** — `reply.status` is then `undefined`. Answer `load()` / `form()` callers with `ajaxReply()` only, and treat a non-object reply as a failure (`shopReply()` in [26](26-CONTROL-SLICE.md) §5).

### Nested `data` + HTTP 400 = “Request failed” (**MUST** — law)

This is how Disable / Test route / Clear looked “broken” while PHP had a real `message`.

`$dotapp().load(url, "POST", { rule: token, enabled: "0" })` does **not** POST a flat object. The body is `{ data: { rule, enabled, csrf… }, crc }`. `$request->data()['rule']` is empty. Decrypt fails. `ajaxReply(..., 400)` makes `fetch` take the **error** path. The toast is generic **Request failed**. `reply.message` never shows.

`$request->form()` nests the same way. `load()` onError is `(httpStatus, bodyText)`, not the success `(raw)` shape.

**MUST:** unwrap (`formBag` / `posted()` of `$request->data()`, or the `form()` bag). Admin product outcomes: HTTP **200** + `status` 0|1 + `message`.

**MUST:** when this class is found on **one** action, grep **this module** for every `load()` / `form()` sibling (`$request->data()[` without unwrap, `ajax(..., 400)`, `ajax(..., 500)`) and fix them in the same chunk. **MUST NOT** ship “Disable works, Delete still 400”. Canonical: [00](00-AGENT-CONTRACT.md) §2q.

**MUST NOT:** product-fail a `load()` / `form()` action as HTTP 400/500 “to be RESTful”. Middleware 403 (anonymous / rights) and prefix CRC 400 stay as they are.

Form submits are routed through this pipeline automatically unless the form has `data-dotapp-nojs`. **There is no full-page reload.** If `.after()` / the `load` callback does not update the DOM, the user sees nothing until they refresh — that is a **bug**.

Helpers: `$dotapp().sendInput(groupName, url)` for `Input::group` forms. **Files:** `$dotapp().uploadFile` — never hand-built `FormData` on `load()` / `<fo-rm>`.

### File uploads (**MUST**)

`$dotapp().load()` and `<fo-rm>` post JSON `{ data, crc }`. A ZIP (or any file) stuffed into `FormData` on that pipeline **cannot** carry the CRC. PHP `crcCheck()` fails (400/403), the AJAX error callback fires, and the user sees a generic “Request failed” instead of the server `message`.

**MUST:** `$dotapp().uploadFile(file, url, progressCallback)` — Promise of response **text**, then `$dotapp().parseReply(text)`. `progressCallback(fileName, percent)` reports real upload progress. On HTTP failure the Promise rejects with an `Error` that carries `.status` and `.responseText` — show `parseReply(error.responseText).message` when it is there. Drop zone: `$dotapp().dragAndDropFile(dropZone, fileInput, callback, parallel)` (it calls `uploadFile`).

**MUST NOT:** `new FormData()` + `load()` / `form()` / `fetch` / `$.ajax`. **MUST NOT** put `<input type="file">` inside `<fo-rm>` and expect CRC to work.

`uploadFile` sends the file as multipart field `user_files` with the header `dotapp: load`. PHP — **MUST** receive it with the core class `Uploader` ([48](48-UPLOADER.md)):

```php
use DotsystemsAppPartsUploader;

if (($_SERVER['HTTP_DOTAPP'] ?? '') !== 'load') {
    return DotsystemsAppDotApp::DotApp()->ajaxReply(['status' => 0, 'message' => 'Bad request'], 200);
}
$result = Uploader::use('Shop')->images()->maxSize(5 * 1024 * 1024)->maxFiles(1)->receive();
if ($result['status'] !== 1) {
    $message = $result['errors'][0]['message'] ?? 'No file arrived. Choose a file and try again.';
    return DotsystemsAppDotApp::DotApp()->ajaxReply(['status' => 0, 'message' => $message], 200);
}
$file = $result['files'][0];       // store $file['name'] (random stored name); $file['original'] is display text only
return DotsystemsAppDotApp::DotApp()->ajaxReply(['status' => 1, 'message' => 'Uploaded.'], 200);
```

`Uploader` checks the upload state, the size on disk, **every** dot-part of the name (`.php.jpg`, `.jpg.php`), the allow-list, the MIME **from the bytes**, decodes and **re-encodes images** (hidden code / polyglots do not survive), and stores the file under a random name in `app/runtime/uploads/{name}` (not reachable by URL). Full API, result shape, error codes, serving and deleting: [48](48-UPLOADER.md).

**MUST NOT** read `$_FILES`, call `move_uploaded_file()`, or hand-write extension / MIME checks in a module. The older pattern — `$request->upload(function (array $files) { … })` with a hand-written checklist — is **legacy**: do not write it in new code. `$request->upload()` only lists the incoming files; it checks nothing and stores nothing.

**MUST NOT** serve a stored file from a URL that ends with an image extension (the web server answers it as a static file, the module never runs) and **MUST NOT** set its headers with plain `header()` — use `Response::contentType()` / `Response::header()` / `Response::cache()` ([48](48-UPLOADER.md) §5).

**MUST NOT** `crcCheck()` on this endpoint — there is no `{ data, crc }`. Guard with `#Shop:Rights@check!` / `Auth::can()`. Return HTTP **200** + `status` 0|1 so the Promise resolves and you toast `reply.message`. HTTP 400/403/500 hits `fetch`’s error path (generic failure). Overlay the drop zone until the Promise settles.

### Interactive UX (**MUST**)

`<fo-rm>` is hijacked by `dotapp.js` (`preventDefault` + `load()`). Native submit / PHP `header('Location')` / hoping the browser reloads **does not run**.

| Stay on this page (list, toggle, add row, inline save) | Leave the page (login, wizard step, “save then open detail”) |
|------------------------------------------------------|--------------------------------------------------------------|
| **MUST** return fresh markup or data in JSON and patch the DOM | `redirectTo` + `window.location` is OK |
| **MUST** show a short, non-blocking toast (“Enabled”, “Saved”) | Toast optional if navigation is immediate |
| **MUST** overlay the region while in flight (desktop **and** mobile) | — |
| **MUST NOT** `location.reload()` / `window.location` as the success path | |

PHP (stay on page) — the module reply helper ([26](26-CONTROL-SLICE.md) §7), always HTTP 200:

```php
return Reply::ok('Enabled.', ['html' => $tableHtml]);                              // re-rendered tbody / list fragment
return Reply::fail('The rule was not enabled: it has no recipient yet.');          // status 0 + the reason
```

JS — the module request helper ([26](26-CONTROL-SLICE.md) §5):

```javascript
shopForm("#shopRuleForm", "#shopRuleCard", function (reply) {
  if (reply.html) {
    $dotapp("#shopRulesInner").html(reply.html);
  }
});
```

`shopForm()` binds `.before()`, `.after()` **and** `.onError()`. `.after(data, rawText, form)` runs only on HTTP 2xx; `.onError(data, status, bodyText, form)` runs on HTTP 4xx/5xx and network faults. A chain with no `.onError()` leaves the form blocked with no toast.

Same rule for `$dotapp().load(...)` (toggles, delete, “add rule”). Bind row actions with `.live()` so they still work after the HTML is replaced. Toast: **DACore admin** → Notiflix (shell). **Public website** → your module notify. Never `alert()`.

### Visible outcome (**MUST**)

The user **MUST** see what happened. Silent save / silent fail is a bug. Law: [00](00-AGENT-CONTRACT.md) §2d.

**DACore admin:** the shell loads Notiflix (`Notify` / `Confirm` / `Block`) and `window.dacoreRequestError` (reads `reply.message` out of an HTTP error body). There is no `$dotapp().toast()`. Use the shell through the one module request helper ([26](26-CONTROL-SLICE.md) §5). Do **not** invent a second toast library. Success and failure = **toast**.

**Public website:** Notiflix is not there. **You MUST build** feedback. Field validation **preferred:** mark the wrong input (red) + message **on that field**. PHP returns `errors` keyed by field.

| Surface | Success / fail | Field errors |
|---------|----------------|--------------|
| `Page@withMenu!` | `Notiflix.Notify.success` / `failure` on `status` 1, on `status` 0 **and** on HTTP/network failure | Toast `reply.message` (field mark optional extra) |
| Public / front-office | Your module toast / status | **Preferred:** red input + text on the field |

Copy-paste: [EX-09](examples/EX-09-validation-and-errors.md), [EX-06](examples/EX-06-dotapp-js-boot.md). Search DACore: [33](33-DACORE-PAGES-AND-UI.md).

**MUST NOT** wrap row actions in `<fo-rm>` (move up/down, drag-and-drop, toggle, delete, paginate). Those are `type="button"` + encrypted `data-*` + `load()`. `<fo-rm>` is only for a real multi-field submit. See [08](08-FORMS-AND-SECURITY.md) “One-shot actions are not forms”.

### Block while in flight (**MUST** — desktop and mobile)

This is **first-class UX**, not decoration. Pages **MUST** feel fast, obvious, and foolproof on a **desktop and on a phone**. Skipping a visible busy state is a bug.

While a request that mutates a region is running, the user **MUST NOT** be able to fire the same or a conflicting action again (double-submit, second drag, extra tap). Cover the region. Ignore further **clicks and touches** until done.

| What is running | **MUST** block |
|-----------------|---------------|
| `<fo-rm>` submit | `blocked` + `$dotapp().halt()`; button `loading`/`loader`; cover the form |
| List toggle / delete / paginate / filter | Cover the **whole list wrapper**; ignore further clicks/taps until done |
| Reorder / drag-and-drop | Cover the **whole list / drop zone** so another drag/touch-move cannot start |

Show the loader **before** `load()` (or in `.before()`). **MUST** remove it in **both** the success and error callbacks (and in `.after()`). A stuck overlay is a bug.

Cover a **stable parent** you do **not** replace entirely; patch the inner fragment (`TBODY`, `#listInner`). Replacing the blocked node’s `innerHTML` wipes the overlay.

**Notiflix is DACore-only** (the admin shell). It is **not** on public / front-office pages.

- **DACore admin** (`Page@withMenu!`): pick **one** stack per page — **Notiflix** (already loaded; preferred) **or** an equivalent in **your module**. Do not re-add Notiflix. Do not patch DACore.
- **Public website** (no DACore shell): **MUST** ship preloaders in **your module**. Notiflix is not there.

Skipping Notiflix on an admin page does **not** waive preloaders. A custom system that fails the UX bar is not acceptable.

**UX bar (MUST — admin and public):**

- Overlay is **visible** on desktop **and** mobile (contrast, spinner large enough to see on a phone).
- Overlay intercepts **pointer and touch**. Hover-only busy states are forbidden.
- Cover the **region being mutated**. On a narrow screen the list/form still looks blocked.
- Do not rely on desktop-only layout for the busy state.
- One in-flight request per region; a second tap/drag is ignored until the overlay is gone.
- Toasts are short and non-blocking. Never `alert()`.
- **Layout (LAW):** every new button/control has padding vs its parent on **all sides** (left, right, top, bottom). Buttons live in `.dacore-card-actions` after `.card-body` (or a `d-flex gap-2` row). `card-footer` / `pb-4` have no CSS rule in the DACore shell. A Save glued to the card edge is a **bug**. Canonical: [00](00-AGENT-CONTRACT.md) §2f, [05](05-VIEWS-TEMPLATES-ASSETS.md) §8c, [33](33-DACORE-PAGES-AND-UI.md) §6.

Notiflix API (when you choose option 1):

```javascript
Notiflix.Block.standard("#listWrap", "Loading…");   // pass a CSS selector string
Notiflix.Block.remove("#listWrap");
Notiflix.Notify.success("Enabled.");
Notiflix.Notify.failure(window.dacoreRequestError.message(status, bodyText, "The request did not reach the server"));
```

These four calls belong in **one** place — the module request helper `shopSend()` / `shopForm()` ([26](26-CONTROL-SLICE.md) §5). Handlers call the helper; they do not repeat block / parse / toast / unblock.

**MUST NOT:** leave the list draggable/tappable during save; start a second `load()` on the same region while the first is in flight; forget to remove the overlay on the error path; empty `.after()` / empty `load` success callback; `alert()`; rely on a full reload “so the table updates”; skip overlays because “we didn’t use Notiflix”.

Copy-paste: [examples/EX-06-dotapp-js-boot.md](examples/EX-06-dotapp-js-boot.md).

### Public website mobile navigation (**MUST**)

This is **not** the DACore admin shell (`Page@withMenu!` already has its menu — do not rebuild it). It is for a **public / front-office site** you build in the current module.

A layout that looks finished on a wide monitor and fails on a phone is a **bug**. Desktop-only chrome (inline links, hover dropdowns, search in a wide bar) **MUST** have a matching mobile UX in the **first** version.

**Drawer (MUST):**
- A control (hamburger) in a **sticky/fixed mobile header** (logo + button) opens a panel that **slides in from the left or the right**.
- The panel **overlays** the page (scrim). It does **not** squeeze the site into a leftover column and does **not** push the document down as a long stack of links.
- While the drawer is open, the **page behind MUST NOT scroll** — including iOS. `overflow: hidden` on `html`/`body` **and** `position: fixed; width: 100%` on `body` with saved `scrollY` (restore on close). Touch-move on the scrim must not scroll the site.
- The drawer itself **MUST scroll** when items do not fit (`overflow-y: auto` on the **nav list**; close control + search stay reachable above the list).
- Close: icon, tap on the scrim, Escape, and after choosing a link.
- Touch targets large enough to tap. Nested items: tap to expand — **MUST NOT** hover-only submenus on a phone.

**Search and contacts (MUST unless the user declined):**
- Phone, email, address, and a **compact** search field belong **inside the mobile drawer** — not only in a desktop header that vanishes on a small screen. Typical order: close, compact search, contacts, then the **scrollable** link list.
- If the user asked for a **large / faceted / full-page search**, do **not** cram it into the drawer. Ship a **dedicated mobile search section** (own screen or full-width panel). A compact shortcut in the drawer is still fine.

```css
/* classes: {lowercase_modulename}_* */
html.shop_navopen { overflow: hidden; }
body.shop_navopen { overflow: hidden; position: fixed; width: 100%; }
.shop_scrim { position: fixed; inset: 0; z-index: 40; }
.shop_drawer {

  width: min(20rem, 86vw); z-index: 41;
```

```javascript
function shopNav(open) {

        document.body.style.top = "-" + y + "px";
        $dotapp("html,body").addClass("shop_navopen");
```

**MUST NOT:** hide the desktop nav on mobile with no drawer; leave the document scrollable under an open menu; a menu taller than the viewport with no inner scroll; drop contacts/search on mobile because “no room in the header”.

### Paginate accumulating lists (**MUST** — ship it, interactive, no reload)

Two failures, **both bugs**:

1. **No pager** on a list that can grow (users, logs, items, orders, messages, files, events) — even if the table is empty today.
2. A pager that **reloads the admin shell** (`<a href="?page=2">`, `location.reload()`, full navigation). That is not interactive.

Agents **MUST NOT** dump the table with `->all()` ([06](06-DATABASE.md)). Skip a pager **only** for a set that is closed by product design (four fixed cards). **“Few rows now” is not a skip.**

The pager **MUST** be **interactive AJAX**: stay on the page, overlay the list (Notiflix preferred **or** module) while the request runs, `$dotapp().load()`, patch `html` (rows **and** pager), remove overlay on success **and** error. Desktop **and** mobile. The overlay is a busy state — it is **not** a page reload.

**Law (HTML, classes, `live` signature, COUNT, CRC Referer):** [40-DACORE-LIST-PAGER.md](40-DACORE-LIST-PAGER.md). Copy-paste: [EX-D08](examples/EX-D08-list-pager.md).

First paint may be server-rendered page 1. Further pages: POST with encrypted `page` plus current filters. Pager: `type="button"` + `.live()` — **MUST NOT** `<fo-rm>` per page button. `DACore:Page@paginate!` with a **`$callable`** that emits buttons — do not pass a `?page=` `$href`. **MUST NOT** `history.replaceState` of `?page=` — that burns CRC on the next POST.

`$dotapp().live(event, selector, fn)` calls **`fn(el, e)`**. The first argument is the **element**. `function (e) { e.currentTarget }` silently no-ops.

```javascript
$dotapp().live("click", ".shop-page", function (el, e) {
  if (e && typeof e.preventDefault === "function") e.preventDefault();
  if (!el || el.disabled) return;
  var page = $dotapp(el).attr("data-page") || "";
  if (!page) return;
  shopSend("/api/v1/auth/Shop/items/list", { page: page, q: currentQuery }, "#listWrap", function (reply) {
    $dotapp("#listInner").html(reply.html);
  });
});
```

SQL: `QueryObject::paginate($perPage, $page)` — it returns the real `total` and `last_page` ([40](40-DACORE-LIST-PAGER.md) §4). Copy-paste: [examples/EX-D08-list-pager.md](examples/EX-D08-list-pager.md), [examples/EX-06-dotapp-js-boot.md](examples/EX-06-dotapp-js-boot.md).

### Choice control vs searchable list (**LAW — do not confuse them**)

A **list page** and a **single-value picker** are different UX problems:

| Need | Required control |
|------|------------------|
| Browse a growing collection (users, logs, products, orders, messages) | SQL `COUNT` + `LIMIT`, AJAX pager, and appropriate list search/filter |
| Choose one value from a known small/bounded set (installed modules, languages, statuses, backup target) | Native `<select>` that exposes the complete choices |
| Choose one value from a longer but still bounded set | Existing `$dotapp(el).dotSelect2(...)`; opening it **MUST** show choices before typing |
| Choose from a genuinely large/unbounded remote dataset | AJAX-backed `dotSelect2` with initial results, paging, and server search |

**MUST NOT** replace a known choice set with a bare text/search input, empty `datalist`, or custom typeahead that requires the operator to remember and type an exact name before any choices appear. This is not “interactive list search”; it is a hidden picker and a UX bug.

**DACore:** search first and use the existing `dotSelect2`. Do not create another typeahead or Select2 wrapper. A native select is preferred when all choices fit comfortably. Use `dotSelect2` when search materially helps, not merely because the control selects a record.

If scale is uncertain, **ASK** whether the product expects a bounded picker or a growing catalogue. Do not infer “AJAX search” from the word *select*, *module*, *owner*, or *lookup*.

### Interactive AJAX search on lists (**MUST ASK** / often **MUST ship**)

A pager without search is incomplete UX on a growing list the operator **browses or filters** by name, title, SKU, or number. This section applies to result tables/list pages, **not** to a form control that chooses one known option.

**When planning a list, ASK in chat** (do not guess, do not skip the question):

| Kind of list | Default |
|--------------|---------|
| Lookup content: articles, products, catalog, customers, orders by number | **Ship search** unless the user says no |
| Users, logs, rights rows, short admin tables | **ASK:** “Do you want interactive AJAX search on this list?” |

**MUST (when search is in):** same stay-on-page contract as the pager. Overlay the list (Notiflix preferred **or** module), `$dotapp().load()`, patch rows **and** pager. Desktop **and** mobile.

**MUST:**

- Filter **in SQL** with `paginate()` — **MUST NOT** `->all()` then filter in JS
- Debounce typing (~300 ms). Run a search from **3 characters**. Empty / shorter than 3 = unfiltered page **1**

- When `q` is set and `total` is 0: show a **no matches** line (product copy), not a blank table
- **Search DACore first** for an existing search field chrome; otherwise the input lives in **your** module ([33](33-DACORE-PAGES-AND-UI.md))

## 4. Custom `$dotapp` libraries (plugins / FE modules)

**Never edit** `app/parts/js/` (`dotapp.js`, `dotapp.template.js`, `dotapp.reactive.js`). Those are core. Put your library in **your PHP module**: `app/modules/<YourModule>/assets/js/...` → `/assets/modules/<YourModule>/js/...`.

Source of truth for the API: `app/parts/js/dotapp-docs.html` (read-only). Shipped add-ons to copy the **pattern** from (read-only): `dotapp.template.js`, `dotapp.reactive.js`.

### Events

| Event | When | Use for |
|-------|------|---------|
| `dotapp-register` | fires **first**, core is ready to accept `fn()` | **Register** libraries |
| `dotapp` | fires after register | **Use** `$dotapp` in page code |
| `dotapp-template-ready` / `dotapp-reactive-ready` | official add-on loaded | optional wait |
| `dotapp-<yourname>-ready` | your lib finished `fn()` | optional wait |

Page logic listens to `dotapp`. Libraries listen to **`dotapp-register`**. Mixing them up is the usual bug.

### `fn(name, callback)`

`$dotapp().fn('shopHighlight', function (...) { ... })` hangs the function on every DotApp instance as `$dotapp('#el').shopHighlight()`.

- `this` is the DotApp instance. Selected nodes: `this.getElements()`.
- `fn()` returns `true` when it registered the function. A taken name (a method of `dotapp.js`, or a function registered earlier) is **never overwritten**: `fn()` changes nothing, returns `false` and warns in the console — no exception. Keep the `isRegistered` flag (a file loaded twice must not set up its state twice). A `try/catch` around `fn()` in older libraries is harmless.
- **MUST** prefix every name with the module (`shopFlash`, `shopStars`) and write it in camelCase. A taken name is silently **not** registered — the call then runs the existing function and does something else than you expect. **MUST** check that `fn()` returned `true` (warn otherwise) and **MUST NOT** pick a name `dotapp.js` or another library already has. Call the function through `$dotapp(...)`, not through the result of `fn()`.
- Load order **MUST** be `dotapp.js` → library → page script. A page script before the library fails with `TypeError: $dotapp(...).shopStars is not a function`.
- A widget whose elements are replaced by `html()` **MUST** be applied again to the new elements. Text a library writes into the page **MUST** go through `textContent`, not `innerHTML`.
- Always wrap in an IIFE. If `window.$dotapp` already exists, call `runMe` immediately; else wait for `dotapp-register` (`{ once: true }`).
- HTTP from a library **MUST** use `this.load` / `this.form` / `this.uploadFile` / bridge — never `$.ajax` / raw `fetch` to DotApp endpoints. Files **MUST NOT** go through `load()` as `FormData`.
- Per-element widgets: one node → return the instance API; many → return `this`. Chainable helpers always `return this`.

### A. Chainable helper (return `this`)

```javascript
(function () {
    var isRegistered = false;
    var runMe = function ($dotapp) {
        if (isRegistered) { return; }
        isRegistered = true;

        $dotapp().fn('shopHighlight', function (color) {
            color = color || 'yellow';
            this.getElements().forEach(function (el) {
                el.style.backgroundColor = color;
            });
            return this;
        });

        window.dispatchEvent(new Event('dotapp-shophighlight-ready'));
    };

    if (window.$dotapp) {
      runMe(window.$dotapp);
    } else {
      window.addEventListener(
        "dotapp-register",
        function () {
          runMe(window.$dotapp);
        },
        { once: true }
      );
    }
})();
```

Usage (after `dotapp`): `$dotapp('#box').shopHighlight('red').addClass('active');`

### B. Instance module (official `template` / `reactive` / connector pattern)

One instance per DOM node, cached on the element. Register on `dotapp-register`. Throw if the selector is not exactly one element when that is required.

```javascript
(function () {
    var isRegistered = false;

    var runMe = function ($dotapp) {
        if (isRegistered) { return; }
        isRegistered = true;

        function ShopChart(dotApp, settings) {
            this.dotApp = dotApp;
            this.settings = settings || {};
        }
        ShopChart.prototype.refresh = function () {
            var self = this;
            // Why: a GET must have no data object — load(url, 'GET', {}) sends a body and fetch rejects it.
            this.dotApp.load(this.settings.url, 'GET', null, function (raw) {
                var reply = self.dotApp.parseReply(raw);
                if (!reply || typeof reply !== 'object' || reply.status != 1) {
                    Notiflix.Notify.failure((reply && reply.message) || 'The chart data could not be loaded.');
                    return;
                }
                // draw the chart from reply here
            }, function (status, body) {
                Notiflix.Notify.failure(window.dacoreRequestError.message(status, body, 'The chart data could not be loaded'));
            });
        };

        $dotapp().fn('shopChart', function (settings) {
            var key = '_shopChart';
            var els = this.getElements();
            if (els.length !== 1) {
                throw new Error('shopChart requires exactly one element');
            }
            var el = els[0];
            if (!el[key]) {
                el[key] = new ShopChart(this, settings);
            }
            return el[key];
        });

        window.dispatchEvent(new Event('dotapp-shopchart-ready'));
    };

    if (window.$dotapp) {
      runMe(window.$dotapp);
    } else {
      window.addEventListener(
        "dotapp-register",
        function () {
          runMe(window.$dotapp);
        },
        { once: true }
      );
    }
})();
```

Usage: `var chart = $dotapp('#sales').shopChart({ url: '/shop/chart' }); chart.refresh();`

Porting **is** writing a new library. Do **not** wrap `$.fn.foo` (`$(el).plugin()` inside `$dotapp().fn` is not a port). Rewrite in vanilla DOM, then hang it on `$dotapp` with `fn()`.

**When porting, ask the user** (usually yes). jQuery may stay for leftover UI; **every request** still uses `$dotapp().load` / `form` / bridge.

Do **not** write a second copy. Do **not** copy DACore JS into your module. Read those files **read-only** as shape examples. Put **your** port in `app/modules/<YourModule>/assets/js/` — never into `app/modules/DACore/` or `app/parts/js/`. Canonical: [33](33-DACORE-PAGES-AND-UI.md) “Search DACore first”.

#### Playbook

0. **Search first** ([33](33-DACORE-PAGES-AND-UI.md)): grep DACore (read-only) and your module. If the widget exists, **stop** and use it.
1. Keep the **public API shape**: `$('#el').select2(opts)` → `$dotapp('#el').dotSelect2(opts)` (or `{modulename}Picker`).
2. Keep **CSS class / markup** when you want drop-in HTML (`select.select2`, `.toast`, `.modal`, `data-bs-*`). Extra DACore styling uses `{lowercase_modulename}_*` in **your** CSS.
3. Vanilla constructors. Cache instances in a `WeakMap` or `el._key`. No `$` inside the library.
4. Register on **`dotapp-register`**. Guard with `isRegistered`; check that `fn()` returned `true` (a taken name returns `false` and is not overwritten).
5. Loop `this.getElements()`. **One** node → return the widget API. **Many** → return `this`. Empty `$dotapp().fn` call → factory (dynamic modal / notify manager).
6. Optional `autoInit()` on `DOMContentLoaded` for markup hooks. Skip nodes with `data-{name}-skip` or an existing instance.
7. Dispatch `dotapp-<name>-ready`. Optional `window.DotXxx = { mount, get }` for callers that are not on the chain.
8. Replace `$.ajax` / `$.getJSON` with `this.load` + `parseReply`. File uploads: `this.uploadFile` — never `FormData` on `load()`. `fetch` is only OK for static/public files that do not go through CRC.
9. Bind **document** click/keydown once in `runMe` for dismiss/toggle (`data-bs-dismiss`, `data-bs-toggle`) — do not attach one listener per instance.

## 5. Bridge (PHP ↔ JS)

### Template syntax — all modifiers

```html
<input type="text" {{ dotbridge:input="email" }} />
<button {{ dotbridge:on(click)="ping(email)" regenerateId oneTimeUse rateLimit(60,10) internalID(shop.ping) expireAt(1767225600) url(/shop/bridge) }}>
  Ping
</button>
```

| Form / flag | Meaning | Default |
|-------------|---------|---------|
| `dotbridge:on(event)="fn(a,b)"` | call PHP `fn` on a DOM event | — |
| `dotbridge:on(event,key)="fn()"` | e.g. `on(keyup,Enter)` | — |
| `dotbridge:input="filter.name(args)"` | live input validation attributes | — |
| `regenerateId` | rotate the request id after each call | off |
| `oneTimeUse` | single use (also applies a 30-day/1 limit) | off |
| `rateLimit(seconds,count)` | repeatable rate limit | none |
| `internalID(id)` | stable session storage key | hash of function name |
| `expireAt(timestamp)` | absolute expiry | `0` (disabled) |
| `url(path)` | custom POST target (bound + verified) | current route |

Built-in input filters for `dotbridge:input`: `email`, `url`, `phone`, `password`, `date`, `time`, `creditcard`, `username`, `ipv4`. Add your own with `Bridge::addFilter($name, $callback)`.

### PHP registration

```php
// Bound to the URL of the page that shows the button (the call is POSTed to that same URL).
// $pageUrl MUST also be in initializeRoutes(), or the module is asleep when the call arrives.
Router::bridge($pageUrl, 'ping', function ($request) {
    $email = $request->data(true)['data']['email'] ?? '';
    if ($email === '') {
        return ['ok' => false, 'message' => 'Missing email'];
    }
    return ['ok' => true];
}, Router::STATIC_ROUTE);

// Controller string form (preferred):
Router::bridge($pageUrl, 'ping', 'Shop:Home@ping!', Router::STATIC_ROUTE);
```

The return value becomes the `body` of the JSON response. Non-callable handler → **`\Exception`**.

**MUST (verified 2026-11-15 on core 2.1.0):** register with `Router::bridge($url, $name, $handler, Router::STATIC_ROUTE)` (closure or controller string) or `Bridge::listen(...)` with the same arguments. `$dotApp->bridge->fn('name', …)` called from `initialize()` answered **404 / error_code 3** for the same button. The input **MUST** be declared with `{{ dotbridge:input="name" }}` (renders `dotbridge-input="name"`); a bare `dotbridge="name"` attribute is not collected and the value is missing from `$request->data(true)['data']`.

**Port:** `dotapp.js` posts bridge and `fo-rm` requests to `protocol//hostname` (no port). An app served on a non-standard port sends them to the default port — serve the app on 80/443.

### JS hooks

```javascript
$dotapp()
  .bridge('ping', 'click')
  .before(function (data, el) {})
  .onValueError(function (inputName, el) {})
  .after(function (body, el) { /* body = PHP return value */ })
  .onResponseCode(function (status, text, el, e) {}, 429)
  .onResponseCode(function (status, text, el, e) {}, 403);   // one call per status code; a handled code does not also fire onError
```

### Response and error codes

Success: HTTP 200, `{ status: 1, body: <your return>, ... }` plus regenerated ids when `regenerateId` is set. Header `X-Answered-By: dotbridge`.

| HTTP | `error_code` | Trigger |
|------|--------------|---------|
| 400 | 1 | CRC check failed |
| 403 | 2 | bridge key mismatch |
| 403 | 5 | CSRF referer mismatch |
| 403 | 6 | invalid `dotbridge-url` |
| 404 | 3 | function not registered / not callable |
| 429 | 4 | rate limit, invalid id, or missing valid key |

### Security order (never bypass)

1. `dotbridge-key` matches the session bridge key
2. CRC over the posted `data`
3. decrypted internalID present in the session's valid set
4. rate limit check
5. decrypted CSRF referer tab equals `HTTP_REFERER`
6. optional URL binding check
7. `oneTimeUse` consumption
8. decrypt the function name and invoke, with before/after hooks

### Storage limit

`Config::bridge('storage_limit')` (default **200**) caps stored bridge listeners per session; the oldest entries are **evicted FIFO**. Override with `Bridge::max_keys($n)`. On a page with very many bridge buttons, older ones can stop working — prefer fewer, parameterised endpoints.

## 7. Reactivity: variables, binding, computed (`dotapp.js`)

```javascript
$dotapp().variable('qty', 1).variable('price', 120);          // variable() returns $dotapp() (chaining)
var qty = $dotapp().getVariable('qty');                         // the variable itself
var price = $dotapp().getVariable('price');
var total = $dotapp().computed(function () { return qty.value * price.value; }, 'total');

qty.value = 3;                                                  // bound elements, computed, callbacks follow
qty.onChange(function (oldValue, newValue) { });                // listener: .off() .pause() .resume()
cart.update(function (items) { items.push(item); });           // arrays/objects changed in place
```

```html
<input type="number" dotbind="qty">                      <!-- two-way, live while typing -->
<strong dotbind="total"></strong>                         <!-- text (textContent), computed with a name -->
<div dotbind="preview" dotbind-html></div>               <!-- HTML: only trusted content -->
```

| Rule | |
|---|---|
| **MUST** take the variable with `getVariable(name)` | `variable()` returns `$dotapp()`, `.value` on it is `undefined` |
| **MUST** assign a new value or use `update()` / `notify()` for arrays and objects | `push()` alone notifies nobody |
| **MUST** read dependencies through `.value` inside `computed` | that is how they are tracked; a computed **MUST NOT** write variables |
| **MUST NOT** put user text into `dotbind-html` / `{ html: true }` | plain binding is text and safe; HTML binding executes markup |
| Elements added later (`html()`, `append()`) | **MUST** call `$dotapp('#box').dotbind()` to bind their `dotbind` attributes |
| Saving a value | `variable.autosave({ url, debounce, data, onSuccess(reply), onError(error, reply) })` posts with `load()`: PHP `crcCheck()` once, value in `$request->data(true)['data']['value']`, name in `['name']`; answer `ajaxReply` HTTP 200 + `status` |
| Values are strings from fields | convert (`Number(qty.value)`) before arithmetic |

Use reactivity for **one page's live state** (totals, counters, filters, "unsaved changes", previews). The server stays the source of truth: save through `load()` / autosave and re-render from the reply. **MUST NOT** build a client-side copy of a whole list or a SPA store with variables.

```html
<script src="/assets/dotapp/dotapp.reactive.js"></script>
<span reactive-api="/shop/api/unread" reactive-interval="30000"></span>
```

```javascript
var unread = $dotapp().reactive('/shop/api/unread', { interval: 30000, variable: 'unread' })
    .after(function (reply) { /* reply = parsed ajaxReply */ })
    .onError(function (error) { });
unread.refresh();   // ask now
unread.destroy();   // stop
```

- Config: `method` (`GET`), `interval` (ms), `trigger` (DOM event, or `'variable'`), `variable` (name — gets the **whole parsed reply**), `element`, `template`. Attributes: `reactive-api`, `reactive-method`, `reactive-interval`, `reactive-trigger`, `reactive-variable`, `reactive-template`, `reactive-id` (read once at start, then removed).
- Without a trigger the first request goes out **at once**, then every `interval`. While the tab is hidden no request is sent; when it becomes visible again a missed refresh runs at once.
- Without `variable` and `template` the element gets the reply as **HTML** (`innerHTML`) — only for HTML your server built. With `variable` the element is not touched: render in `after()` or bind the variable.
- `GET` goes through `load(url)` without data and **without CRC** — read-only endpoints only; rights still apply. Anything that changes data is a `POST` through `load()` + `crcCheck()`.
- The PHP class `Dotsystems\App\Parts\Reactive` is **not started by the framework**; endpoints are ordinary routes answering `ajaxReply`.

## 8. jQuery trap summary

| jQuery habit | DotApp |
|--------------|--------|
| `$('.x')` | `$dotapp('.x')` |
| `$.ajax` / `$.post` | `$dotapp().load(...)` |
| chained getters | assign to a variable |
| `$(fn)` | `dotapp` event |
| `.on()` on dynamic nodes | `.live(...)` |
| plain `<form>` + `_token` | `<fo-rm>` + `{{ formName(...) }}` |
| raw JSON response | PHP `ajaxReply()` (base64 JSON) + JS `parseReply()`; never `Response::json()` for a `load()` / `form()` caller |
| static `dotapp.js` copy | `/assets/dotapp/dotapp.js` |
