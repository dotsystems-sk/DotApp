# 02 — DotApper CLI

**Tool:** `dotapper.php` (DotApper 1.2)  
**Run from project root** (directory containing both `dotapper.php` and `index.php`).  
Module paths use `./app/modules` relative to **CWD**.

```powershell
Set-Location "D:\path\to\project-root"
php .\dotapper.php --help
```

CLI-only: non-CLI HTTP requests get 403.

---

## Flag reference

### Documented commands

| Flag | Syntax | What it does |
|------|--------|--------------|
| Help | `--help` or `?` | Print help |
| Install framework | `--install` | Download DotApp zip into script dir (interactive) |
| Update framework | `--update` | Update from GitHub zip; preserves `index.php`, `app/config.php`, `app/listeners.php`, `dotapper.php` |
| Create module | `--create-module=<Name>` | Full scaffold under `app/modules/<Name>/` |
| Create example module | `--create-example-module=<Name>` | Slimmer scaffold (no `tests/`) |
| List modules | `--modules` / `--list-modules` | Numbered list |
| Select module | `--module=<number\|name>` | **Selector only** — must precede generators |
| Create controller | `--module=… --create-controller=<Name>` | Stub in `Controllers/` |
| Create middleware | `--module=… --create-middleware=<Name>` | Stub in `Middleware/` |
| Create model | `--module=… --create-model=<Name>` | Stub in `Models/` |
| Create .htaccess | `--create-htaccess` | Write root `.htaccess` |
| List routes | `--list-routes` | Boot app, print routes |
| List one route | `--list-route=<path>` | e.g. `--list-route=/` |
| Optimize modules | `--optimize-modules` | Write `app/modules/modulesAutoLoader.php` |
| Core tests | `--test` | Framework tests, or module tests if `--module` set |
| All module tests | `--test-modules` | All modules' tests |
| Prepare DB SQL | `--prepare-database[=prefix]` | Export prefixed SQL file (interactive) |
| Install module | `--install-module=<git_url\|name>[:version]` | External module install |

### Hidden / companion flags

| Flag | Purpose |
|------|---------|
| `--force` | Overwrite existing module dir on `--install-module` |
| `--github-token=<token>` | Private GitHub installs |
| `--install777` | Hidden install path (avoid) |
| `--create-modules` | Parsed but **no-op** |

### Order rule

```powershell
# CORRECT
php .\dotapper.php --module=MyModule --create-controller=Home

# WRONG — module not selected for the generator
php .\dotapper.php --create-controller=Home --module=MyModule
```

## What each generator creates

### `--create-module=<Name>`

Directories: `assets/`, `Api/`, `Controllers/`, `Libraries/`, `Models/`, `Middleware/`, `translations/`, `views/`, `views/layouts/`, `tests/`

Files:

- `module.init.php`, `module.listeners.php`
- `Api/Api.php`, `Controllers/Controller.php`
- `views/clean.view.php`, `views/layouts/example.layout.php`
- `AI_RULES.md` — a short pointer: if `/AIRULES` exists in the project root, follow it (start with `00-AGENT-CONTRACT.md`)

Dotapper does **not** embed or generate `AIRULES/`. The rulebook ships with the framework.

Module name is `ucfirst()`'d. Namespaces: `Dotsystems\App\Modules\{Name}\…`

> DotApper no longer writes the old `MODULE_AI_guide.md` / `VIEWS_AI_guide.md` / `CONTROLLERS_AI_guide.md` / `TESTS_AI_guide.md` / `TRANSLATION_AI_guide.md` / `ASSETS_AI_guide.md` stubs. They taught incorrect syntax and were removed; `/AIRULES` replaces them.

### `--create-controller / --create-middleware / --create-model`

Writes one PHP stub; **does not overwrite** if file exists.

### Not generated by CLI

Libraries, views (beyond scaffold), translations JSON, assets, tests PHP classes, cron, cache clear, composer, user creation, permissions assignment, module uninstall.

## Interactive prompts

Commands that ask `[Y/n]:` (Enter = yes): `--install`, `--update`, `--prepare-database`, `--install-module`.

**No `--yes` flag.** Pipe confirmation:

```powershell
"y" | php .\dotapper.php --install
"y" | php .\dotapper.php --prepare-database=myprefix_
```

---

## Agent policy

1. Always `Set-Location` to project root before running.
2. Prefer generators over hand-written skeletons.
3. After adding modules / route patterns for lazy load: consider `--optimize-modules`.
4. Review generated stubs — they contain example comments; replace with real code.
5. Expect exit quirks (see [15-KNOWN-ISSUES.md](15-KNOWN-ISSUES.md)); judge success by printed messages and files created.
